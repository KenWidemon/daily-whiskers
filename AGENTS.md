# Repository Guidance

Agent workflow rules; update when repository conventions change.

- Follow `docs/branching-strategy.md` for branch and PR work.
- Before adding or changing documentation, apply the admission and retention rules
  in `docs/README.md`. Read only the other guides relevant to the task.
- Update the canonical guide alongside affected behavior; do not add session logs,
  handoff recaps, duplicate backlogs, or raw test output to the repository.
- Keep scope/priorities in GitHub Issues/Projects, personal planning in Apple Notes
  / Side Hustle, reviewer correspondence in App Store Connect, and raw evidence in
  private artifact storage. Verify external saves before removing unique material.
- Preserve concise release provenance, explicit deferrals and unresolved risks.
  Follow the issue-status workflow in `docs/README.md`; do not infer acceptance from
  a merged PR or substitute historical tests for current validation.
